# Автодополнение и подсказки для Kotlin/Java в редакторе Warpium

Исследование от 2026-11-19, пункт 18 роадмапа. Ветка `master` (база `28c57a21e`). Продолжает
[kotlin-navigation-and-toolchain.md](kotlin-navigation-and-toolchain.md): там выбрана стратегия
«сначала Rust-индекс, потом ленивый LSP», здесь она проверена на автодополнении. В PR есть
прототип: `CodeIndex::complete` в `crates/code_index/src/resolve/complete.rs` с unit-тестами и
строками `complete (…)` в бенчмарке. В редактор он не подключён. Ссылки на код Warp даны как
`файл:строка` на базе `28c57a21e`. Внешние источники прочитаны 2026-11-19.

---

## 1. TL;DR

1. **В редакторе кода Warp автодополнения нет совсем.** Ни LSP, ни AI, ни простого по словам.
   LSP-клиент (`crates/lsp`) умеет definition, references, hover, formatting и diagnostics, но
   `textDocument/completion`, `signatureHelp` и `inlayHint` даже не объявлены в capabilities.
   AI-подсказки Warp (ghost text, предсказание команд) живут только во вводе терминала и ходят на
   сервер Warp. Готовые кирпичи при этом есть: синхронизация буфера с LSP по дельтам, тултип hover
   с Markdown, позиционирование карточки у символа, инкрементальное дерево tree-sitter у каждого
   буфера, меню подсказок терминала как образец UI.
2. **Рекомендация: гибрид, но в первом PR только индекс.** Автодополнение из
   `crates/code_index` работает мгновенно и без фоновых процессов:
   - **2–3 мс p95 на 100 тыс. символов** и 3–6 мс на 258 тыс. (прототип, контейнер, release);
   - **ноль дополнительной памяти** (индекс уже загружен для навигации);
   - **KMP «из коробки»**: source sets и `expect`/`actual` индекс уже понимает.

   LSP (`kotlin-lsp`, jdtls) остаётся опциональным уточнителем: он подключается позже, по
   проекту, и никогда не блокирует ввод. AI ghost text — последняя, опциональная фаза.
3. **Качество индекса упирается в библиотеки, а не в алгоритм.** На ссылках, которые индекс
   резолвит, нужное имя стоит в топ-5 в **89–94%** случаев после одной набранной буквы и в
   **92–96%** после трёх (первым в 50–76%). Но по всем ссылкам в списке есть только **46–66%**
   имён. Остальное — Kotlin stdlib, AndroidX и Android SDK, которых в индексе нет. Отсюда
   главный рычаг качества после первого PR: индексировать `-sources.jar` из Gradle-кэша и
   `android.jar`. Это фаза 4 навигационного исследования, теперь она важнее.
4. **Типизация без компилятора даёт члены только там, где тип записан рядом.** Это параметр,
   `val x: Foo`, `val x = Foo()`, свойство класса, `this`, имя класса или объекта. Цепочки
   `a.b().c.` и результаты вызовов функций без вывода типов не резолвятся. На них прототип
   честно помечает список как приблизительный (`≈`) и подставляет члены с подходящими именами.
5. **Подсказки дешевле всего тоже из индекса.**
   - **Quick doc:** KDoc/Javadoc читаются с диска по `start_line` декларации, память не нужна.
     Рисуются существующим рендером hover.
   - **Parameter info и тип в строке списка:** нужно один раз дописать в индекс текст списка
     параметров и объявленный тип. Это `FORMAT_VERSION` 4, по оценке около 2–4 МБ на 100 тыс.
     символов.
   - **Inline hints:** дешёвые только для имён параметров в вызовах.
   - **Ошибки:** честные ошибки даёт только LSP. Из tree-sitter дёшево получаются лишь
     синтаксические.
6. **Бюджет производительности для первого PR:**
   - `complete()` ≤ 5 мс p95 на 100 тыс. символов и ≤ 10 мс на 258 тыс.;
   - на главном потоке только снимок буфера и клон дерева;
   - каждый запрос на background executor, устаревшие отменяются;
   - большие файлы через инкрементальный reparse дерева редактора: **0,25 мс вместо 23 мс** на
     файле 267 КБ (замер в этом исследовании).

## 2. Что уже есть в Warp

### 2.1. LSP-клиент (`crates/lsp`)

- **Серверы.** `LSPServerType` (`crates/lsp/src/supported_servers.rs:40`): `RustAnalyzer`,
  `GoPls`, `Pyright`, `TypeScriptLanguageServer`, `Clangd`. Kotlin и Java нет. Enum
  персистится в sqlite, поэтому новые варианты добавляются только в конец.
- **Capabilities клиента.** `default_client_capabilities()` (`crates/lsp/src/config.rs:284`)
  объявляет synchronization, definition, hover (Markdown) и publishDiagnostics. **Нет
  `completion`, `signatureHelp`, `inlayHint`, `semanticTokens`, `codeAction`.** Сервер не
  будет присылать completion, даже если умеет.
- **Запросы.** `TextDocumentService` (`crates/lsp/src/service.rs`): `definition` (`:595`),
  `format` (`:640`), `hover` (`:671`), `references` (`:701`). Обёртки в `LspServerModel`
  (`crates/lsp/src/model.rs`): `goto_definition`, `hover`, `find_references`,
  `diagnostics_for_path`.
- **Синхронизация буфера.** `GlobalBufferModel::notify_lsp_of_content_change`
  (`app/src/code/global_buffer_model.rs:1547`) шлёт `didChange` дельтами, а при рассинхроне
  целиком. Это готовая основа: LSP-completion потребует только нового запроса, не новой
  синхронизации.
- **Запуск и opt-in.** `PersistedWorkspace::detect_available_servers_for_workspaces`
  (`app/src/ai/persisted_workspace.rs:521`) вызывает `should_suggest_for_repo` у каждого типа
  сервера. Результат хранится как `EnablementState::Suggested/Yes/No` на корень workspace: это
  и есть механизм «включить для проекта». Неиспользуемые серверы гасит
  `LanguageServerShutdownManager`, сканируя раз в 10 с
  (`app/src/code/language_server_shutdown_manager.rs:21`).
- **LSP для агента.** Флаг `FeatureFlag::LSPAsATool` (`crates/warp_features/src/lib.rs:650`)
  отдаёт LSP агенту Warp как инструмент.

### 2.2. Редактор кода (`app/src/code`, `crates/editor`)

- **Hover.** `LocalCodeEditorView::hover_for_offset`
  (`app/src/code/language_server_extension.rs:302`) срабатывает по наведению мыши с debounce
  (`local_code_editor.rs:511`) или с клавиатуры (`show_hover_at_cursor`,
  `local_code_editor.rs:2353`). `render_hover_tooltip` (`language_server_extension.rs:467`)
  рисует Markdown с подсветкой кода и диагностиками в прокручиваемой карточке. Это готовый
  рендер для quick doc и parameter info.
- **Позиционирование попапа у символа.** `compute_card_positioning`
  (`local_code_editor.rs:871`) ставит карточку над или под символом по
  `character_bounds_in_viewport`. Попап completion позиционируется тем же способом, под
  курсором.
- **Карточка списка.** `FindReferencesView` (`app/src/code/find_references_view.rs`) — список
  в карточке у строки, с клавиатурной навигацией.
- **Декорации.** `Decoration` (`crates/editor/src/render/model/mod.rs:5713`) поддерживает
  только фон и пунктирное подчёркивание (диагностики). **Inline virtual text (inlay hints,
  ghost text посреди строки) нет.** Есть `TemporaryBlock` (`crates/editor/src/content/edit.rs:144`):
  целые «призрачные» строки перед строкой буфера, сейчас для удалённых строк диффа. Есть
  `BufferText::Placeholder` (`crates/editor/src/content/text.rs:568`) для ghost text в
  блочных редакторах. Для inlay hints и однострочного AI ghost text нужна новая возможность
  рендера.
- **Дерево синтаксиса.** `SyntaxTreeState` (`crates/syntax_tree/src/lib.rs:79`) держит дерево
  tree-sitter каждого буфера и обновляет его инкрементально по дельтам (`tree.edit` +
  `parse_with_options` со старым деревом). Файлы больше 2 МБ не парсятся
  (`MAX_PARSE_BYTES`, `:30`). Kotlin и Java подключены через `arborium` (`crates/languages`).
  Completion может брать отсюда дерево и не парсить файл заново.
- **Навигация Warpium.** `LocalCodeEditorView::request_code_index_navigation`
  (`local_code_editor.rs:2161`) копирует текст буфера и позицию в `CodeNavigationRequest`
  (`app/src/warpium/code_navigation.rs`). Workspace резолвит запрос на background executor.
  Привязки действуют там, где у keymap-контекста есть флаг `WarpiumCodeNavigation`.
  Completion ляжет на тот же путь.

### 2.3. Подсказки в других местах Warp

- **Меню completions во вводе терминала.** `InputSuggestions` (`app/src/input_suggestions.rs:195`)
  — 1 300 строк: список с иконками по виду элемента, панель подробностей, выделение,
  прокрутка. Это образец UI и источник иконок (`bundled/svg/completion-*.svg`), но вид
  жёстко завязан на терминал, и переиспользовать его как есть нельзя.
- **Ghost text во вводе терминала.** Автоподсказки команд (`app/src/editor/view/mod.rs`,
  `ACCEPT_AUTOSUGGESTION_KEYBINDING_NAME`). AI-предсказания следующей команды и запросов
  агенту (`app/src/ai/predict/`, `FeatureFlag::AgentPredict`, `PredictAMQueries`) ходят на
  сервер Warp и требуют аккаунта Warp.
- **Для редактора кода ничего из этого нет:** ни автодополнения, ни AI «next edit».

## 3. Варианты

### 3.1. Автодополнение из индекса Warpium (прототип в этом PR)

**Как устроено** (`crates/code_index/src/resolve/complete.rs`, около 650 строк вместе с
тестами):

1. **Фиктивный идентификатор.** Набранный префикс берётся до курсора. После курсора
   вставляется фиктивный идентификатор `WarpiumCompletionDummy`, как `IntellijIdeaRulezzz` в
   IntelliJ, и файл парсится. Так `foo.` становится корректным `foo.<id>` в настоящем
   синтаксическом контексте. В Java без точки с запятой узел превращается в `ERROR`, поэтому
   там в конце пустой строки добавляется `;`. Дальше работает тот же классификатор
   (`classify`), что у Go to Definition.
2. **`receiver.`** Тип ресивера ищется уже существующим `Resolver::receiver_type`:
   локальная переменная или параметр с типом, `val x = Foo()`, свойство класса, `this`, имя
   класса или объекта, `new Foo()`, `Foo(...)`. В список попадают:
   - члены этого типа и супертипов до 3 уровней, с учётом импортов файла-декларации;
   - для статического доступа — члены companion object, вложенные типы, enum entries и Java
     `static`;
   - extension-функции и свойства для этих типов, с автоимпортом, если они не видны.

   Если тип не найден, в список идут члены с наиболее подходящими именами из всего индекса
   (`approximate = true`). Без префикса в этом случае список пуст.
3. **Простое имя.** Сначала идёт обход областей видимости, в порядке ранжирования:
   - локальные переменные (идентификаторы раньше курсора во внешней функции, проверенные через
     `find_local`);
   - декларации файла и члены, унаследованные внешними классами;
   - явные импорты (с alias);
   - после первой буквы — пакет и star-импорты;
   - top-level декларации всего индекса с автоимпортом (не больше 200 лучших имён, только
     префикс или camel humps с первой буквы);
   - «слова»: имена, которые файл уже использует, но индекс не знает. Это библиотечные
     `remember`, `LaunchedEffect`, `viewModelScope`.
4. **Ранжирование.**
   - Совпадение: префикс выше camel humps, а camel humps выше совпадения со «словом
     внутри».
   - Источник: local > member > scope > import > package > star import > extension > не
     импортировано > слово.
   - Код проекта выше тестов и generated, короткие имена выше длинных.
   - Дубли (одна декларация, найденная двумя путями) убираются.

**Бенчмарк.** `script/warpium/code_index_bench` теперь печатает строки `complete (N typed)`.
Методика:

- берутся те же примерно 550 ссылок, что у Go to Definition (имена после точки и имена с
  заглавной);
- имя стирается, набираются первые 0, 1 или 3 символа, вызывается `complete`;
- «resolved» — ссылки, которые индекс резолвит точно (не декларации): только на них можно
  честно проверить, что нужное имя есть в списке;
- «listed (все)» — доля всех ссылок, имя которых оказалось в топ-50.

Условия: Linux-контейнер, 4 потока, release, тёплый индекс.

| Корпус | Символы | 1 буква: p50 / p95 / max | 3 буквы: p95 | После точки, 1 буква: p95 | Топ-5 / первым (resolved, 1 буква) | Топ-5 / первым (3 буквы) | В списке среди всех ссылок (1 / 3 буквы) |
|---|---|---|---|---|---|---|---|
| nowinandroid | 2,0 тыс. | 0,22 / 0,79 / 1,4 мс | 0,80 мс | 0,79 мс | 90% / 50% | 93% / 59% | 57% / 62% |
| Thunderbird | 37 тыс. | 0,35 / 1,07 / 2,5 мс | 1,19 мс | 1,02 мс | 91% / 51% | 93% / 60% | 55% / 59% |
| DuckDuckGo | 114 тыс. | 0,88 / 2,23 / 6,0 мс | 2,12 мс | 2,11 мс | 89% / 56% | 92% / 65% | 63% / 66% |
| Signal | 105 тыс. | 0,77 / 2,66 / 58 мс* | 2,70 мс | 2,60 мс | 89% / 57% | 92% / 66% | 53% / 56% |
| Все четыре одним корнем | 258 тыс. | 1,46 / 3,07 / 9,2 мс | 3,54 мс | 4,64 мс | 94% / 64% | 96% / 76% | 46% / 51% |

\* Все выбросы приходятся на один файл, `MessageTable.kt`: 267 КБ и 7 тыс. строк. Его полный
парс tree-sitter стоит 23 мс сам по себе. Инкрементальный reparse дерева после вставки строки
стоит 0,25–0,29 мс (замер в этом исследовании), поэтому в приложении completion должен брать
дерево редактора (`SyntaxTreeState`), а не парсить файл заново. Остаток выброса (до 110 мс без
префикса) — обход сотен членов гигантского класса. Он лечится отменой устаревших запросов и
лимитом на число имён.

**Что показали первые прогоны.** Первая версия прототипа делала `SymbolInfo` (аллокации) для
каждой декларации пакета или контейнера до проверки имени и сканировала все имена индекса.
Итог: 23–53 мс p95 на 100–258 тыс. символов. Две правки опустили это до 2–5 мс:

- фильтровать по interned-имени до аллокации;
- для «чужих» имён сравнивать только имена с той же первой буквой (префикс и camel humps с
  первого слова всегда начинаются с неё).

Вывод: бюджет 5–10 мс достижим только с такой дисциплиной, и бенчмарк обязан её стеречь.

**Память.** Запрос держит только разобранный текущий файл и список кандидатов, постоянной
памяти не добавляется. Индекс тёплого процесса по-прежнему 7–77 МБ RSS (2 тыс.–258 тыс.
символов).

**Пределы качества:**

- **Нет вывода типов.** Не резолвятся `foo().bar.`, `list.first().`, `it.` в лямбде (тип `it`
  не записан), smart casts, generics (`List<User>` даёт члены `List`, а не `User`) и тип
  выражения `val x = repo.load()`. IntelliJ здесь точен, индекс — нет.
- **Нет библиотек.** Kotlin stdlib (`let`, `map`, `orEmpty`), AndroidX/Compose и Android SDK в
  индекс не попадают. Это и есть разница между 89–96% по resolved-ссылкам и 46–66% по всем.
- **Не учитываются** область `internal` по модулям, `protected` вне иерархии, named arguments
  и ключевые слова (их надо добавить отдельным списком).
- **Перегрузки** показываются отдельными строками без сигнатур, пока индекс не хранит списки
  параметров (раздел 4).

### 3.2. LSP по требованию

**JetBrains `kotlin-lsp`** ([repo](https://github.com/Kotlin/kotlin-lsp),
[docs](https://kotlinlang.org/docs/kotlin-lsp.html),
[releases](https://github.com/Kotlin/kotlin-lsp/releases)):

- **Что умеет.** Completion «IntelliJ-powered», diagnostics с quick fixes, hover, semantic
  highlighting, rename, organize imports, форматирование, call hierarchy. Signature help и
  inlay hints в списке возможностей не названы.
- **Статус.** Alpha, Apache-2.0, сервер частично закрытый (см. предыдущее исследование).
- **KMP.** **Новое с 12 ноября (v271.2085.0):** «Kotlin Multiplatform Gradle projects are now
  imported», с common и платформенными source sets и KMP-библиотеками. На kotlinlang.org пока
  написано «under development». Значит, для KMP-проектов владельца kotlin-lsp впервые стал
  реальным кандидатом, но это нужно проверить руками. Android (AGP) по-прежнему
  experimental.
- **Ресурсы.** Предыдущее исследование: 2–5 ГБ RSS в двух процессах, `initialize` ждёт полного
  Gradle-импорта (2–5 минут на Android-проекте), дистрибутив около 400 МБ, для запуска нужен
  JDK. В [issue #94](https://github.com/Kotlin/kotlin-lsp/issues/94) на монорепо из 60+
  проектов и примерно 3 тыс. файлов около 19 ГБ памяти, 100+ ГБ аллокаций за 2 минуты и
  GC-паузы около секунды. В v271 заявлено «analysis no longer stalls other requests when the
  server is low on memory». Задержку completion на больших проектах никто не публиковал.
  Ориентир — IntelliJ: десятки или сотни миллисекунд на запрос и заметно дольше на холодном
  кэше.
- **Как запускать.** Новый `LSPServerType::KotlinLsp` в конце enum. Скачивание zip, как у
  `rust-analyzer` и `clangd` (`crates/lsp/src/install.rs`). `JAVA_HOME` в env процесса
  (`LspServerConfig` сейчас передаёт только `PATH`). Режимы Off / On demand / Auto на проект
  через `EnablementState`. Старт при первом открытии `.kt` в проекте с `Yes`. Остановку уже
  делает `LanguageServerShutdownManager`, но для Kotlin лучше поднять порог простоя с 10 с до
  минут: перезапуск стоит минуты.

**Eclipse JDT LS** ([repo](https://github.com/eclipse-jdtls/eclipse.jdt.ls)):

- зрелый сервер для Java с completion, Maven и Gradle, Android-импорт experimental;
- рантайм Java 25+, EPL-2.0;
- в примере запуска `-Xmx1G`, на крупных проектах на практике 1–2 ГБ;
- смысл есть только для Java-тяжёлых проектов (Signal) и только как opt-in.

**fwcd/kotlin-language-server:** объявлен deprecated, не рассматривается.

**kmp-lsp** ([repo](https://github.com/Hessesian/kmp-lsp), MIT): Rust и tree-sitter, без
JVM, «under 200 MB», hover, definition, completion, rename. Это тот же класс решения, что наш
индекс. Полезен как референс эвристик, но второй процесс с дублем индекса нам не нужен.

**Общий вывод по LSP.** LSP даёт то, чего индекс не может: вывод типов, библиотеки, ошибки
компиляции. Но он стоит гигабайты и минуты, поэтому никогда не должен стоять между нажатием
клавиши и попапом. Важный бонус: completion, signature help и inlay hints в `crates/lsp`
нужно сделать **одинаково для всех серверов**, и тогда Rust, Go, Python, TypeScript и C++
получат автодополнение в редакторе Warpium сразу. Это пункт «later other languages» почти
даром.

### 3.3. AI inline-подсказки

- **Встроенного в Warp нет.** AI-предсказания Warp есть только для терминала и требуют сервер
  и аккаунт Warp (раздел 2.3). Для форка, который не ходит на серверы Warp за обновлениями, это
  не опора.
- **Варианты провайдера** (FIM, fill-in-the-middle):
  - локальная модель через Ollama или llama.cpp: Qwen2.5-Coder 1.5B–7B, StarCoder2;
  - облачный FIM-API (Codestral и подобные);
  - агенты владельца (Claude Code, Codex, Kimi): это диалоговые инструменты с секундами на
    ответ, они не подходят для подсказок на каждое нажатие.
- **Оценки, не замер.** Локальная модель 1,5B на Apple silicon отвечает за 100–300 мс на
  короткую вставку и занимает 1–2 ГБ, модель 7B — 4–5 ГБ. Облако даёт 200–800 мс сети.
- **Цена в коде.**
  - Нужен однострочный inline ghost text в рендере редактора (сейчас только целые строки
    `TemporaryBlock`, раздел 2.2).
  - Обязательные debounce 250–300 мс (как `DEBOUNCE_AI_QUERY_PREDICTION_PERIOD` во вводе
    терминала), отмена на каждое нажатие и принятие по Tab.
  - Отдельно приватность: кусок файла уходит модели.
- **Вывод:** полезное дополнение, но последней фазой и строго opt-in. Ни одна из целей «не
  тормозить» и «скромная память» им не помогает.

### 3.4. Гибрид

Индекс отвечает всегда и сразу. LSP, если включён и готов, запрашивается параллельно:

- если ответ пришёл за 150 мс (ориентир, как у VS Code), его элементы сливаются с индексными;
  точные заменяют `≈`, библиотечные добавляются;
- позже — список обновляется на месте, только пока пользователь не двигал выделение.

AI ghost text показывается отдельно, только при закрытом попапе. Так ведут себя IntelliJ
(completion плюс Full Line), VS Code (completion плюс inline suggestions) и Zed.

## 4. Подсказки: parameter info, quick doc, inline hints, ошибки

| Подсказка | Из индекса | Что добавить в индекс | Из LSP |
|---|---|---|---|
| **Quick documentation** (F1 / `ctrl-J` в JetBrains) | Да. KDoc/Javadoc — блок `/** … */` сразу над `start_line` декларации, читается с диска при показе (одно чтение файла, оценка — доли миллисекунды). Рендер — `render_hover_tooltip` с Markdown. `@param`/`@return` форматируются в таблицу | Ничего | `hover` уже реализован |
| **Тип и сигнатура в строке списка** (`fun load(id: Long): User`) | Нет | Текст списка параметров и объявленного типа или возвращаемого значения: `Sym` в `Symbol` (interned), `FORMAT_VERSION` 4. Оценка: около 2–4 МБ на 100 тыс. символов | `CompletionItem.detail` |
| **Parameter info** (подсказка аргументов в `(…)`) | Да, после строки выше. Перегрузки по имени через resolver (те же правила, что у definition), текущий аргумент — по запятым в дереве `value_arguments`/`argument_list` | Как выше | `signatureHelp` (добавить в capabilities) |
| **Inline-имена параметров** (`load(id = 42)` серым) | Да, для вызовов, разрешённых точно. Нужен inline virtual text в редакторе | Как выше | `inlayHint` |
| **Inline-типы** (`val x` → `: User`) | Только для `val x = Foo()`, остальное без вывода типов невозможно | — | `inlayHint` |
| **Ошибки** | Синтаксические — узлы `ERROR`/`MISSING` tree-sitter, бесплатно из дерева редактора. «Неразрешённое имя» без библиотек дало бы море ложных срабатываний, не делать | — | `publishDiagnostics` уже рисуется (`refresh_diagnostics`, `language_server_extension.rs:135`) |

## 5. Рекомендация и план

### 5.1. Что делать

**Гибрид по фазам.** Первый PR, большой и законченный (по предпочтению владельца), — это
автодополнение и подсказки из индекса. Он сразу полезен на KMP, ничего не стоит в фоне и
закладывает UI, к которому потом подключатся LSP и AI.

### 5.2. Фаза 1 — первый PR: «Completion и подсказки из индекса»

**`crates/code_index`** (protoc-free, unit-тесты, бенчмарк):

1. Довести `complete` из прототипа:
   - ключевые слова языка (с учётом контекста: внутри класса, после `.` их нет);
   - named arguments внутри вызова (`load(i|` → `id =`);
   - `super.`, `this@Outer.`, `it.` / `this.` в лямбдах с явно записанным типом;
   - импорты и пакеты (`import com.ex|` — пути из индекса);
   - статические импорты Java;
   - `internal` по модулю, `protected` вне иерархии.
2. Сигнатуры в индексе: текст параметров, объявленный тип или тип возврата, `FORMAT_VERSION`
   4. Отсюда detail в строке списка и `signature_help(file, position)` с активным параметром.
3. `documentation(symbol)`: KDoc/Javadoc по `start_line`, приведённый к Markdown.
4. API, которое принимает готовое дерево (`tree_sitter::Tree`) вместе с текстом, чтобы не
   парсить файл. Плюс бенчмарк на больших файлах: p95 ≤ 5 мс включая reparse.

**`app/src/warpium/code_completion.rs`** (новый) и хуки в `LocalCodeEditorView` (по одной
строке, по образцу навигации):

1. **Триггеры:**
   - автопопап после набора первой буквы идентификатора и после `.`;
   - `ctrl-space` — явный вызов: показывает список и без префикса, повторный `ctrl-space`
     добавляет неимпортированные имена и все члены, как второй basic completion в IntelliJ;
   - в строках и комментариях попап не открывается.
2. **Попап:**
   - карточка под курсором (`compute_card_positioning`);
   - иконка вида (class, interface, object, fun, val, enum entry, слово);
   - имя с подсвеченными совпавшими символами;
   - серая сигнатура или тип;
   - справа пакет или «import com.foo.Bar»;
   - бейдж `≈` у приблизительных элементов;
   - справа от списка панель с quick doc выбранного элемента, как в JetBrains (по `ctrl-J` или
     всегда — решить).
3. **Клавиши, как в JetBrains:**
   - ↑/↓ и PageUp/PageDown, пока попап открыт;
   - Enter вставляет; Tab заменяет остаток идентификатора справа от курсора;
   - Esc закрывает;
   - продолжение набора фильтрует на месте без нового запроса, пока префикс только растёт;
   - для функций курсор встаёт внутрь `()`, если есть параметры.
4. **Автоимпорт.** При выборе элемента из `NotImported`/`Extension` вставляется строка
   `import …` в отсортированное место блока импортов одной правкой (undo в одно действие).
5. **Parameter info.** Открывается автоматически на `(` и `,`, обновляется при движении
   курсора внутри вызова. Отдельная команда «Show parameter info» с редактируемой привязкой
   (JetBrains `cmd-P` занят палитрой команд Warp, раздел 6).
6. **Quick doc.** Команда «Quick documentation» (`F1`, редактируемая): при наличии LSP —
   hover, иначе индекс. Тот же рендер hover.
7. **Потоки:**
   - на главном потоке только снимок текста (`Arc<str>`), клон дерева, позиция и номер
     версии;
   - запрос уходит на background executor под read-lock индекса;
   - ответ применяется, только если версия буфера не изменилась. Устаревшие запросы
     отменяются (`AbortHandle`), одновременно не больше одного;
   - индекс ещё строится → попап показывает то, что есть, с пометкой «Indexing…», как палитры.
8. **Включение.** Настройка `warpium.code_completion` (по умолчанию включена, OSS channel)
   плюс «Enable/Disable code completion» в палитре. Отдельные тумблеры для автопопапа и
   parameter info. На время разработки — `FeatureFlag::WarpiumCodeCompletion` в
   `DOGFOOD_FLAGS`.
9. **Тесты:**
   - unit-тесты на триггеры, фильтрацию, вставку и автоимпорт (`*_tests.rs` с `warpium` в
     пути, чтобы их гонял Warpium Tests);
   - проверка в VM: попап, автоимпорт, parameter info, отсутствие подлагиваний при быстром
     наборе в `MessageTable.kt`.

### 5.5. Как бенчмаркать

```bash
script/warpium/code_index_bench                # все четыре корпуса, строки "complete (N typed)"
script/warpium/code_index_bench --combined     # плюс 258 тыс. символов одним корнем
cargo run --release -p code_index --example bench -- --name private /path/to/project
```

В каждой строке `complete (N typed)`:

- p50/p95/max по примерно 550 ссылкам;
- доля всех ссылок, имя которых попало в топ-50;
- для ссылок, которые индекс резолвит точно, — доли «первым», «в топ-5» и «в списке»;
- строка `after a dot` повторяет то же для доступа к членам.

PR, меняющие ранжирование или источники кандидатов, прикладывают таблицу до и после. Падение
топ-5 больше чем на 2 пункта или рост p95 больше чем на 20% — повод разобраться до merge.
Замеры на Mac — только на release-сборке (см. «CI» в WARPIUM.md). В контейнере держать корпуса
вне `/workspace`.

## 6. Открытые вопросы владельцу

1. **Автопопап или только по вызову?** JetBrains по умолчанию показывает список при наборе.
   Предлагаю так же, с настройкой «только по `ctrl-space`».
2. **`ctrl-space` занят.** В Warp это глобальное «New Agent Mode pane»
   (`app/src/util/bindings.rs:403`). Перебить его в контексте редактора кода (Warpium-флаг
   keymap) или выбрать другую клавишу? Parameter info в JetBrains — `cmd-P`, а это палитра
   команд Warp. Предлагаю авто-показ на `(` и `,` плюс редактируемую привязку, например
   `alt-cmd-P`.
3. **Библиотеки в индексе (фаза 4).** Индексировать `-sources.jar` из Gradle-кэша и
   `android.jar`? Это главный рычаг качества: даст 85%+ вместо 46–66%, но добавит диск и
   память (оценка: десятки МБ снапшотов на проект). Делать сразу после фазы 1 или после LSP?
4. **kotlin-lsp.** С v271 заявлен KMP-импорт. Проверить его на `kmp-bspb-demo` в фазе 3? Сколько
   RAM вы готовы отдать: 2–5 ГБ на проект, режим «On demand» по умолчанию?
5. **AI ghost text.** Нужен ли вообще, и если да — локальная модель (Ollama) или облачный
   FIM-API? Отправка кода в облако по умолчанию выключена.
6. **Панель quick doc рядом со списком** — всегда или по `ctrl-J`, как в JetBrains?
